# 大模型算法课程大纲与授课提示词

> 学习起点：熟悉 Python，学过基础机器学习；深度学习、数学熟练度、每周时间和 GPU 条件尚未确认。
>
> 项目主线：为你正在做的戒色／冲动管理 App 建设能够理解用户目标、提供即时支持、记住经授权的信息，并根据行为反馈改善体验的 AI 系统。
>
> 资料核验日期：2026-10-06。斯坦福课程版本指本次能核实的公开版本；近期案例主要取自 2025—2026 年，个别采用 2024 年预印本、2025 年发表的研究。正式授课时再次核验。

## 1. 学完以后，你应该能做什么

这套课程把算法原理、工程代码、斯坦福课程与作业、个人产品四条线放在一起。每个板块都回答三个问题：算法为什么成立、代码怎样运行、它是否真的适合你的用户。

完成后应能展示以下成果：

- 从张量、损失和梯度出发，独立实现一个小型 Decoder-only Transformer，解释训练与生成过程。
- 理解数据清洗、训练稳定性、计算预算、KV Cache、注意力优化和部署成本。
- 比较 Prompt、RAG、记忆、SFT、LoRA、DPO 与推理强化学习，按证据选择方法。
- 为 App 建设一条“用户发起求助 → 理解当前情境 → 给出可选支持 → 用户反馈”的完整路径。
- 用用户主动提供的行为记录改善推荐，处理冷启动、缺失数据、误报和提醒疲劳。
- 设计能够复现的模型评估与产品实验，区分模型表现、用户体验和行为效果。

**最终有两个交付物：一个用于理解原理的小型语言模型，一个用于产品的 AI 支持助手。**前者使用公开或合成文本；后者优先评估现成模型、规则与检索的组合。小模型的训练结果不构成面向真实用户提供健康支持的能力证明。

## 2. 个人化设定与学习安排

### 根据你已有项目调整工程路线

当前仓库 README 描述了 React 界面、Node.js 后端、本地 JSON 存储和 Melius 聊天入口。这里仅据文档安排学习，不表示已经审计当前实现。

- 算法实验：Python、NumPy、PyTorch；先自己实现核心计算，再与库实现比较。
- 产品实验：保留现有 App 作为交互载体，先通过服务端调用模型；需要本地 Python 模型时再增加独立推理服务。
- 第 01 课用本地 mock 或评估样例建立输入输出协议；第 17 课形成生成式支持基线；第 35 课完成与 App 的集成。
- 所有练习默认使用合成用户与虚构记录。真实用户的日记、聊天和性行为记录不因“用于上课”而自动成为训练数据。
- 推理、检索、训练分别记录版本与成本。不要为了完成课程一次性重写整个 App。

### 时间与设备的默认假设

共 **9 个板块、36 节主课**。每节讲解与案例约 60—90 分钟，核心作业约 3—5 小时；复杂训练、GPU 优化和毕业项目可以拆为多次。预留复习后，按每周约 8 小时安排 **6—9 个月**，再按前四节的实际用时调整。

每节只有一份必做作业，附加挑战不计入主线。完整斯坦福原版大作业可能需要额外数十小时；课程内的缩小练习不能等同于完成原版作业。

| 可用条件 | 核心完成方式 | 对应限制 |
|---|---|---|
| 普通 CPU 电脑 | 小张量、微型语料、很小的 Transformer、模拟环境、mock 模型接口 | 检查原理与正确性；缩小训练不能复现大模型性能 |
| Apple Silicon Mac | 优先 CPU 验证，支持时使用 PyTorch MPS | MPS 不等同于 CUDA；不要求在 Mac 上复现 Triton CUDA 内核或 NVIDIA 性能数据 |
| 可用单张 CUDA GPU | 小模型训练、LoRA、指定 GPU 内核实验 | 先按模型、序列长度、精度和优化器估算显存；不保证任何模型一定能装入某张卡 |
| 少量云算力预算 | 本地完成调试，再运行必要的 GPU 实验 | 每次先给出预计时长、费用和停止条件；价格与供应状况以当时官方资料为准 |

## 4. 课程大纲：每节一份作业

表中的验收条件用于自学，不是斯坦福官方评分要求。作业围绕同一个实验目录持续增量，避免每课重新创建项目。所有“用户记录”默认指合成记录；所有“改善效果”默认是待验证目标。

### 板块一：从机器学习基础进入语言模型（01—04）

目标：把概率、梯度和表示学习连接起来，能读懂张量形状、损失和最小训练循环。

经典案例：[word2vec，2013](https://arxiv.org/abs/1301.3781)，分析词如何变成可计算的向量。近期案例：[Qwen3 Embedding，2025](https://arxiv.org/abs/2506.05176)，比较句子表示、检索与重排序。迁移问题是“如何找到相似情境的支持内容”，不把语义相似等同于用户心理状态。

参考：CS224N 表示学习与反向传播讲义；CS336 张量与资源核算讲义。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 01 | **语言模型到底在学什么**：条件概率、下一个 token、logits、Softmax、交叉熵；区分生成、分类、检索和策略选择。为 App 建立任务地图。 | 写 NumPy 稳定 Softmax 与交叉熵，并提交 10 个虚构求助样例和任务分类。验收：大 logits 不溢出、概率和为 1；明确哪些任务先用规则。 |
| 02 | **梯度如何变成学习**：链式法则、反向传播、PyTorch autograd、batch 与广播。用小型 MLP 理解训练循环。 | 手算一个两层网络的关键梯度，再用自动微分与有限差分核对。验收：解释形状和误差容限；在微型训练集上 loss 能下降，并检查独立验证集。 |
| 03 | **分词与向量表示**：字符、字节、BPE、词表、Embedding；中文、emoji 与敏感文本的 token 成本。 | 实现教学版 BPE 的训练、编码、解码，检查至少 10 个中文／英文／emoji 样例。验收：无损往返；说明教学版与官方完整 tokenizer 的差距。 |
| 04 | **先建立可以比较的基线**：TF-IDF、向量相似度、简单分类器、数据划分。用合成短记录识别用户明确表达的情境标签。 | 比较关键词规则、TF-IDF＋逻辑回归、一个可运行的预训练向量方案；资源不足时向量项改为设计与离线小样本。验收：报告混淆矩阵与 5 个错误，不把分类结果写成诊断。 |

过关：能解释模型输入、参数、loss 和梯度；能区分 token 表示、语义表示和行为标签。

### 板块二：亲手实现 Transformer（05—08）

目标：从单头注意力搭建到能够训练、生成的小型 Decoder-only 模型。

经典案例：[Attention Is All You Need，2017](https://arxiv.org/abs/1706.03762)，理解原始 Transformer。近期案例：[Qwen3 Technical Report，2025](https://arxiv.org/abs/2505.09388)，分析现代模型配置、稠密／MoE 架构与推理模式。这里只复现可承担的组件，不复现旗舰模型。

参考：CS224N Transformer；CS336 架构；CS336 A1。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 05 | **注意力怎样读取上下文**：Q、K、V，缩放点积、因果 mask、计算复杂度；区分注意力权重与解释证据。 | 自己实现单头因果注意力，与参考矩阵计算核对。验收：修改未来 token 不影响过去位置输出；输出与梯度有明确维度。 |
| 06 | **多头、位置与长序列**：多头注意力、RoPE、上下文长度；理解 GQA 的结构与缓存收益。 | 实现多头注意力与 RoPE；GQA 作为进阶选项。验收：输出形状正确，位置变化产生预期差异，并画出一次 token 的计算路径。 |
| 07 | **完整 Decoder Block**：残差、Pre-Norm、RMSNorm、SwiGLU、输出投影；MoE 的路由与负载均衡作概念扩展。 | 实现一个 Decoder Block，记录参数量与各张量形状。验收：前向和反向可运行、梯度有限；解释去掉残差会改变什么。 |
| 08 | **训练与采样一个微型语言模型**：next-token 标签移位、padding mask、temperature、top-k／top-p。 | 用内置 AdamW 训练很小的 Transformer 并生成文本。验收：能过拟合极小批次、没有标签泄漏；比较三种采样设置并保存失败样例。 |

过关：可以不依赖高层模型封装解释整个 forward；能发现标签错位、mask 错误和训练／验证模式差异。

### 板块三：数据、优化与预训练实验（09—12）

目标：从“模型能跑”进到“训练过程可解释、可复现、可预算”。

经典案例：[Chinchilla，2022](https://arxiv.org/abs/2203.15556)，分析模型规模、数据量与计算预算。近期案例：[FineWeb2，2025](https://arxiv.org/abs/2506.20920)，分析多语言过滤、去重和数据组合。用小规模实验学习研究方法，不把局部拟合外推成可靠的大规模预测。

参考：CS336 数据与缩放讲义；A1、A3、A4。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 09 | **训练数据决定模型学到什么**：来源、质量、去重、近重复、数据污染、训练／验证切分。 | 为小型公开文本建立清洗管线，并注入重复与坏样本检查。验收：记录每步保留率，抽查错误过滤；切分后相似内容不轻易跨集合泄漏。 |
| 10 | **优化器与训练稳定性**：SGD、AdamW、权重衰减、warmup、学习率、梯度裁剪。 | 实现教学版 AdamW，和库实现做相同步长的小张量对照；再比较两组学习率。验收：更新值在容差内一致，保留 loss 与梯度曲线。 |
| 11 | **参数、FLOPs、显存与 Scaling Laws**：资源核算、拟合、外推、误差和预算约束。 | 对三档可承担的小模型记录参数、token 数、耗时与验证 loss，练习拟合并保留一个未参与拟合的点。验收：写明拟合不确定性，不据此声称预测了工业规模性能。 |
| 12 | **完成一次可复现的预训练实验**：seed、配置、checkpoint、验证、消融与数据版本。 | 汇总前课代码，完成一次基线和一个单变量消融；资源不足时只做极小规模。验收：别人能按 README 重跑；断点恢复有效，结果与解释对应。 |

过关：能判断 loss 下降来自算法、数据还是实验条件变化；记录失败和无收益结果。

### 板块四：推理加速与模型系统（13—16）

目标：理解为什么模型慢、为什么占显存，以及如何用测量判断优化收益。

经典案例：[FlashAttention，2022](https://arxiv.org/abs/2205.14135)，学习 IO 感知的精确注意力。近期案例：[DeepSeek-V3，2024 年底预印本、2025 年研究版本](https://arxiv.org/abs/2412.19437)，讨论 MLA、MoE 与训练系统；结合 [CS336 2026 讲义代码](https://github.com/stanford-cs336/lectures)分析优化。不要把论文集群效果直接当成你的设备表现。

参考：CS336 推理、GPU、内核、并行讲义与 A2。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 13 | **生成为什么逐 token 发生**：prefill、decode、KV Cache、首 token 延迟、吞吐与流式输出。 | 为微型模型实现 KV Cache，对比缓存与无缓存。验收：同样输入的 logits 在容差内一致；计时包含预热与设备同步，分别记录两阶段。 |
| 14 | **FlashAttention 与 Triton 入门**：显存层级、分块、在线 Softmax、融合算子、profiling。 | 所有人实现 CPU／PyTorch 分块注意力并核对结果；有 CUDA 时再完成一个小 Triton 内核。验收：先证明数值正确，再报告实际设备性能；无 CUDA 不虚报 GPU 加速。 |
| 15 | **混合精度、并行与内存**：FP32／BF16、梯度累积、checkpointing、DDP、分片思想；解释 MoE 通信代价。 | 对同一个微型训练任务比较全批次与等效梯度累积，记录可测资源；多 GPU 时选做 DDP。验收：控制损失归约与随机性，区分实测、估算和架构推断。 |
| 16 | **模型部署与质量成本曲线**：量化、连续批处理、路由、缓存、超时；端侧与云端取舍。 | 在固定的 20 个合成请求上比较两个可获得的推理配置。验收：同时报告质量、p50／p95 延迟、token 用量与成本；不可运行的方案标为未测。 |

过关：能把瓶颈定位到计算、内存、网络或排队；即时支持场景优先关注等待体验。

### 板块五：提示、微调、偏好与推理学习（17—20）

目标：理解不同后训练方法改变什么，什么时候值得训练，什么时候应改数据或流程。

经典案例：[LoRA，2021](https://arxiv.org/abs/2106.09685)与 [DPO，2023](https://arxiv.org/abs/2305.18290)，分析参数高效适配与偏好优化。近期案例：[DeepSeek-R1，2025 首发、2026 年 1 月修订](https://arxiv.org/abs/2501.12948)，学习可验证奖励、推理训练与蒸馏的研究路径。数学奖励能验证答案，不等于能验证健康支持是否有益。

参考：CS224N 后训练；CS336 A5；CS224R 策略梯度、偏好与推理讲义。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 17 | **Prompt 与 In-context Learning**：指令、少样本、上下文预算、结构化输出、模型能力边界。 | 建立 App 支持基线：比较固定支持卡、零样本、少样本三种方案，使用 20 个未用于改提示词的合成场景。验收：输出可解析、选择可执行，有失败与超时兜底。 |
| 18 | **SFT 与 LoRA／QLoRA**：训练目标、chat template、assistant loss mask、低秩更新、过拟合。 | 先手写 LoRA Linear 并验证冻结参数；有算力时用小模型训练，没算力时用微型模型完成。验收：只更新目标参数，比较训练前后独立验证集；不将真实敏感日记混入训练。 |
| 19 | **RLHF、奖励模型与 DPO**：偏好对、策略与参考模型、KL、DPO loss、奖励投机。 | 实现 DPO loss，用虚构回复构造偏好对，并分析至少 3 对有争议样例。验收：交换偏好标签有正确影响；偏好标准不奖励羞辱、迎合或无依据承诺。 |
| 20 | **PPO、GRPO 与可验证推理**：策略梯度、baseline、组内相对优势、采样、奖励校验；蒸馏作延伸。 | 在可验证的算术或小型合成任务上实现奖励与组内优势计算，做一次小实验；完整 RL 训练选做。验收：处理同组全对／全错与零方差，不以最终奖励代替独立评估。 |

过关：知道 RAG 添加信息、SFT 改变任务行为、偏好训练改变选择倾向；三者不互相替代。

### 板块六：RAG、上下文与可控记忆（21—24）

目标：让支持回答与可追溯知识、用户明确授权的信息相连接。

经典案例：[RAG，2020](https://arxiv.org/abs/2005.11401)，学习检索与生成的组合。近期案例：[LongMemEval-V2，2026](https://arxiv.org/abs/2605.12493)，研究长期记忆评估；检索代码参考 Qwen3 Embedding 2025。记忆 benchmark 的分数不能证明你的用户被理解或获益。

参考：CS224N RAG 与工具；CS224G 2026 上下文讲义。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 21 | **RAG 的最小完整实现**：知识来源、切块、BM25、索引、引用与检索失败。 | 用 20—30 条有来源说明的教学支持材料搭建 BM25 检索，再接 mock 或真实模型。验收：区分教学草稿与经审核健康内容；无命中文本时不编造来源。 |
| 22 | **语义检索与重排序**：向量、余弦、混合检索、reranker、Recall@k、MRR。 | 用固定问题集比较 BM25、向量、混合／重排方案。验收：人工相关性标签先于调参，分别报告检索指标与端到端回答质量；小数据先用精确向量搜索。 |
| 23 | **上下文工程与不确定性**：指令、历史、检索结果、预算、来源冲突、拒答；检索文本不是可信指令。 | 写一个 context builder，测试过长历史、冲突来源和含恶意指令的检索文本。验收：不越过 token 预算，有来源日期和优先级，无证据时说明不确定。 |
| 24 | **记住用户，但允许用户改变**：短期状态、长期偏好、时间戳、来源、过期、纠正与删除。 | 实现可查看的记忆表，构造 12 个跨会话用例。验收：目标改变后旧记录失效；推测不写成事实；删除同步覆盖索引与缓存，不能继续检索到旧记忆。 |

过关：能解释为什么检索错、引用错、记忆旧、生成错是不同问题，并分别修复。

### 板块七：工具、Agent 工作流与语音（25—28）

目标：把生成模型放入可控的交互流程，让“做到了”能够被程序状态验证。

经典案例：[ReAct，2022 预印本／2023 发表](https://arxiv.org/abs/2210.03629)，分析推理与行动结合。近期案例：[τ²-bench，2025](https://arxiv.org/abs/2506.07982)，分析多轮对话、工具状态与协作失败。案例用于学习测试方法，不复用其商业场景作为行为支持效果证据。

参考：CS224G 工作流与实时语音；CS224N Agents。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 25 | **结构化输出与工具调用**：JSON Schema、参数校验、权限、读取／写入、工具结果与模型陈述。 | 定义查询目标、列出支持卡、保存用户选择三类工具。验收：拒绝非法参数与越权请求；仅在用户确认记录后写入；不能由模型一句“已保存”冒充成功。 |
| 26 | **把支持过程写成状态机**：明确情境、提供选择、执行、反馈、结束；控制循环和工具预算。 | 实现“求助 → 选行动 → 可选反馈”的工作流。验收：覆盖跳过、拒绝、无效建议、中断、工具失败；用户可随时结束，失败仍能展示固定支持卡。 |
| 27 | **语音、多模态与低延迟交互**：语音识别、合成、流式处理、打断、延迟；情绪推断的局限。 | 用 mock 转写搭建语音交互原型，有条件时接一个语音服务。验收：支持停止、纠正转写与文本回退；默认不存录音，不从声线推断用户的性行为。 |
| 28 | **评估 Agent 的实际完成情况**：工具 trace、状态断言、重复执行、模拟用户与随机失败。 | 建立 15 个工作流场景，重复运行并注入超时、重复请求和错误工具结果。验收：按真实程序状态评分；报告重复运行稳定性，模拟用户不算真实用户研究。 |

过关：能解释何时普通函数或固定工作流更合适；多 Agent 架构仅在单流程遇到具体瓶颈时选修。

### 板块八：用户行为建模与个性化决策（29—32）

目标：用数据回答“此刻适合什么支持”，同时理解预测和因果效果的差别。

经典案例：[HeartSteps 的微随机试验，2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6401341/)，学习决策时点、提醒与短期结果的测量。近期案例：[Oralytics 部署研究，2024 预印本、2025 IAAI 发表](https://arxiv.org/abs/2409.02069)，分析在线学习、反馈与实际部署约束；[2025 官方会议记录](https://aaai.org/conference/aaai/aaai-25/iaai-25-program/)。它们研究运动／口腔健康，迁移的是实验与决策方法，不能据此声称能改善手淫冲动。

参考：CS224R 的策略与奖励基础；本板块的健康行为案例属于补充研究，并非斯坦福大模型作业。

| 课次 | 原理、代码与项目连接 | 本节作业与最低验收 |
|---|---|---|
| 29 | **事件、标签与冷启动**：用户目标、主动记录、时序特征、缺失、选择偏差；规则优先与分层个性化。 | 制作事件字典和 200 条带缺失的合成记录，定义预测时点与标签窗口。验收：特征只用当时已知信息；未记录不当作无冲动；每个字段写明用途与是否必要。 |
| 30 | **预测何时需要支持**：逻辑回归、树模型、时序窗口、校准、误报、阈值与用户分组。 | 比较一条规则与一个普通 ML 模型，LLM 情境标签作为可选特征。验收：按时间／用户合理划分，报告 PR 指标、校准与误报；仅作为支持时机估计，不作诊断。 |
| 31 | **选择什么支持：Contextual Bandit**：探索／利用、LinUCB 或 Thompson Sampling、奖励、约束和“暂不提醒”选项。 | 在合成环境中比较固定规则与一种 Bandit，加入冷启动、静默时段、每日上限、提醒疲劳。验收：记录 regret 与负担；奖励不以聊天时长或连续打开 App 为唯一目标。 |
| 32 | **离线评估与因果推断入门**：反事实、propensity、IPS／DR、positivity、延迟结果、微随机试验。 | 使用已知随机策略生成的模拟日志，完成一个 IPS 估计，并用模拟真值检查误差；DR 选做。验收：说明不可识别情形与方差；不对缺少动作概率的日志硬算可靠因果效果。 |

过关：可以解释“预测有冲动”“用户点击建议”“建议带来改善”为什么需要不同证据。

### 板块九：评估、隐私、集成与毕业项目（33—36）

## 5. 贯穿课程的产品设定

### 一个具体但可调整的场景

虚构用户晚上 23:30 打开 App，主动说：“今天很烦，有点想看片，先帮我缓一下。”用户已明确选择减少色情内容使用；曾授权记录“希望回复简短、不喜欢冥想建议、可以尝试离开房间走一会儿”。

系统需要完成：

1. **理解请求**：这是用户主动发起的支持，不把它自动判断为疾病或失败。
2. **读取必要上下文**：当前目标、用户明确偏好、当前会话；检查记忆是否过期。
3. **给出低负担选择**：两项短行动和“先不选”；建议内容应有适当依据。
4. **执行用户选择**：打开支持卡或计时工具；只有真实工具成功才显示完成。
5. **可选反馈**：用户可以报告有没有帮助，也可以跳过。跳过不作为负面结果。
6. **更新个性化**：确认后的偏好可以记录；模型猜测不自动进入长期记忆。

课程同时用“同样时间但正在工作、不希望提醒”“目标已改为仅减少色情使用”“用户觉得建议令人自责”等反例检查系统。不是所有晚间活动都需要干预。

### 分清四种个性化

| 层次 | 数据与算法 | 什么时候开始 |
|---|---|---|
| 用户明确偏好 | 目标、语言、回复长度、静默时段；规则＋Prompt | 最先实现，新用户也能使用 |
| 会话与记忆 | 用户确认的信息、时间和来源；检索＋上下文 | 能查看、纠正、删除以后 |
| 行为模式 | 主动记录、已知反馈；普通 ML 与校准 | 先证明标签可用、划分正确、优于规则 |
| 个性化行动选择 | 有动作概率与反馈的日志；Bandit／因果评估 | 先模拟验证，再设计适当的真实验证流程 |

把用户个人知识存进可控记忆，通常比直接训练进模型参数更便于纠正和删除。若以后使用数据训练模型，需要单独处理授权、保留期及删除影响；删除原始文件不能保证模型遗忘。

### 衡量哪些体验与结果

- 模型与系统：任务成功、知识依据、记忆正确、结构化输出、工具成功、等待时间、成本。
- 用户体验：是否有帮助、选择是否容易、提醒是否打扰、是否能自主结束、建议无效时能否恢复。
- 行为目标：用户自己选择的目标进展、可感知的控制感、生活影响；明确测量时点、缺失和可能偏差。
- 负面体验：羞耻、自责加重、过度依赖、反复误报、提醒疲劳。

点击、留存、聊天时长、连续打卡只是产品使用数据，不能单独证明行为改善。小规模可用性测试可以发现体验问题，不能据此宣布治疗有效。

产品支持用户自主选择减少或停止；区分手淫、色情内容使用、控制困难、生活影响与道德自责，不仅按频率分类“成瘾”。关于 ICD-11 的临床说明特别区分道德不认可与满足障碍诊断的困扰。[Kraus 等，2018](https://pmc.ncbi.nlm.nih.gov/articles/5775124/)

## 6. 建议的学习项目结构

这是后续逐课建设的目录方案，不表示已创建这些代码或功能：

```text
llm-learning/
  foundations/      # softmax、梯度、BPE、向量基线
  mini_lm/          # Transformer、训练、采样、KV Cache
  systems/          # profiling、分块注意力、资源测量
  post_training/    # LoRA、偏好 loss、可验证任务
  support_ai/       # 检索、上下文、记忆、工具与工作流
  personalization/  # 合成事件、预测、Bandit、离线评估
  evals/            # 场景、评分规则、回归与消融
  experiments/      # 配置、数据版本、指标、失败分析
  learning_log.md   # 进度、错误、下一课入口
```

不把模型权重、真实敏感记录或密钥放进课程提交物。每个实验记录：代码版本、数据来源与切分、模型和依赖版本、seed、设备、预算、指标、失败样例、结论及局限。

## 7. 可直接复制的总授课提示词

**使用方法：把下面整段提示词与本文第 3—5 节一起提供给授课模型；在当前仓库中，可让模型直接读取本文。**只复制提示词而不附大纲时，模型必须先取得大纲，不能凭课号编造课程。

```text
你是我的大模型算法导师，同时具备机器学习研究、PyTorch 工程和 AI 产品评估能力。
请严格依据我附上的《大模型算法课程大纲与授课提示词》授课。
若没有收到大纲且不能读取文件，请先让我提供大纲；不要自行替换课程结构。

【我的起点与目标】
我熟悉 Python，学过基础机器学习。
不要重讲完整 Python 入门，也不要默认我熟练掌握深度学习、矩阵微分或 GPU 系统。
我想做一款面向成年人的戒色／冲动管理 App，帮助有此意愿的人减少不想发生的色情内容使用或手淫行为、改善冲动管理体验。
我希望理解算法原理、独立读写工程代码，结合斯坦福最新可公开获得的课程和作业学习。
既培养通用算法能力，也围绕我的 App 累积成果。
我的现有项目采用 JavaScript／React／Node；算法实验优先 Python／PyTorch，按需要通过接口接入现有 App。
不要为了课程改写整个产品。

【课程与资料】
采用附录大纲的 9 个板块、36 节课，不一次性生成所有课程。
每个板块至少深拆一个经典案例和一个近期案例，来自附录中的一手资料。
核验斯坦福课程年份、课题、作业入口、视频是否公开。
最新版讲义与旧版公开视频必须分开标记；自定义练习与官方作业必须分开标记。
近期案例优先授课时最近 12—24 个月，按教学价值选择，不为了追新强换案例。
涉及接口、模型规格、依赖、硬件支持、价格与平台权限时，核验当时官方资料。
没有联网能力时注明待核验项，不编造新课程、链接、结果或 API。
一课优先阅读不超过 3 份材料，区分必读与选读，并定位应读的章节或主题。

【如何讲原理】
先用一个具体问题解释为什么需要这个算法，再给直觉、公式、数值例子和代码。
公式要解释每个符号、张量形状、输入输出、目标与适用条件。
每节聚焦 3—5 个核心概念，其余作为复习或选修。
给一个能手算或小张量验证的例子，再说明扩大规模以后什么会改变。
区分理论性质、论文作者报告、自己实测和推断。
明确常见失败、反例与适用边界；不要只描述成功路径。
需要数学补课时安排一个短补练，完成后回到主线。

【如何讲工程】
每节给一个完整可运行的教学示例，或者基于上一课的清晰增量补丁。
注明文件位置、运行命令、依赖版本、输入样例和预期现象。
预期现象不是实测结果；未运行的代码明确写“未运行”。
讲清关键张量、设备、dtype、随机性、训练／推理模式、数值稳定性与异常处理。
涉及算法正确性时给针对性核对，例如梯度检查、因果 mask、缓存一致性。
涉及性能时先核对正确性，再计时；说明预热、同步、测量次数和统计方式。
先展示透明的 Python／PyTorch 实现，再引入高层库；不堆叠无必要框架。
训练任务给资源估算、缩小配置和停止条件；没有 CUDA 时给 CPU／MPS 或模拟替代。
不同设备的实验不能冒充相同性能结果。

【官方作业与自定义作业】
授课示例使用独立设计的小问题，不直接复制作业答案。
每节先指出对应的官方课程、主题或作业；无直接对应时明确说明。
做官方作业时读取当期政策，我先独立尝试，你提供概念提示、分层提示和调试反馈。
不直接提供整份官方作业解答，不把缩小练习描述为完成原版。
每节只布置一份大纲指定的核心作业，扩展挑战可选。
核心作业默认 3—5 小时；若预计超时，给 90 分钟最低版与完整分步版。
作业写清任务、交付文件、资源、验收、错误检查和它如何进入毕业项目。
至少要求我亲自解释一个公式、定位一个错误或完成一个关键实现，避免只复制 AI 代码。

【案例拆解格式】
年份与来源 → 问题与基线 → 数据和目标 → 算法机制 → 工程实现 → 评估设计 → 结果及局限 → 可以迁移到我项目的部分。
每个案例必须有明确问题、可阅读的原始资料及一个可验证练习。
模型 benchmark 不能替代我的产品效果证据。
健康行为案例可以迁移决策与研究方法，不能直接推断适用于手淫冲动。

【针对 App 的个性化原则】
先使用用户明确目标、偏好和主动反馈；再考虑记忆、行为预测与策略学习。
区分手淫、色情使用、控制困难、生活影响与道德自责，不按频率诊断。
不羞辱、恐吓或承诺治愈，不把一次偏离说成全部进展归零。
支持用户选择、拒绝、调整目标、跳过反馈和结束对话。
记忆要有来源、时间、纠正、过期与删除；模型推测不能当成用户事实。
不默认跨 App 监控，不把真实敏感对话当练习或训练素材。
无反馈不是无冲动，也不等于建议无效；预测风险不是干预效果。
个性化提醒需要“暂不提醒”、静默时段与负担约束，先在模拟环境验证。
模型或工具失败时仍保留可用的基础支持路径。
行为效果、可用性、模型质量分别评价；临床内容依可靠资料并注明审核需要。

【每节固定输出】
1. 本节情境与问题：与上一课成果如何相接。
2. 三个学习目标和本课前置检查。

6. 斯坦福资料：准确版本、对应主题、官方作业入口和访问限制。
7. App 迁移：至少比较两个方案，说明成本、收益、失败与数据要求。
8. 课堂练习：一个 10—20 分钟任务，先让我尝试，再给提示。

11. 学习记录：已掌握、错误、实验、待核验、项目决策和可复制进度摘要。

【批改与难度调整】
当我提交作业，按原理理解 25、代码正确与可解释 30、实验与证据 25、产品迁移与边界 20 评分，总分 100。
先检查是否能运行和解释，再指出最重要的三个问题，给出具体修复步骤。

若新对话没有历史，先读取进度摘要，不假定前课已经完成。
```
