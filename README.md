# 轻甜 · 工作日减糖陪伴

把甜，留给真正喜欢的时刻。

轻甜由原 Quittr 恢复类原型改造而来，现在面向 **25–35 岁职场女性的工作日减糖场景**：早间甜咖啡、同事下午茶、会议零食、加班之后与聚餐分享。它帮助用户留意饮食与渴望，做一个可持续的小调整；不把一次吃甜食当作失败，不要求完全戒糖、戒碳水或放弃正常饮食。

该人群是本次产品设计的目标与待验证假设，不代表所有女性都有相同需求。应用不默认收集年龄、性别、体重、雇主、经期等信息，也不根据性别推断情绪或健康状态。

| 想吃甜时的支持 | 旧冲动流程与小游戏入口 | 1–5 级自报渴望、当时感受、**一分钟自然呼吸暂停**、小轻对话 | 工作间隙的操作应短而具体；记录渴望不等于记录摄入。用户饿了可以正常吃饭，不把喝水或忍耐当作正餐替代。`SugarDialog`、`BreathingPause`。 |

## 当前能使用的功能

- 邮箱注册、登录、修改密码、退出；服务端会话和私人数据按账号隔离。
- 饮食小记：手动输入，明确区分添加糖、标签总糖和未知；保存支持同一请求标识去重。
- 想吃甜的时刻：选择场景、自报渴望程度、留一句感受；不自动认定发生了摄入。
- 每日温和回顾、个人小目标、心情日记与七天记录图表。
- 小轻 AI 对话：SSE 流式回复、失败重试、原文证据约束、建议卡、饮食与日记归档。
- 精选入门小课及基于真实减糖记录的 AI 小课；读完保存选择，不把选择写成已完成的行为。
- 登录用户共享的“同路人”：主动发布、回应、支持。私人日记与对话不会自动公开。
- 完整数据导出、本机数据库备份、管理员密码重置、Mac 登录后常驻运行。
- iPhone 网页适配、添加到主屏幕；另有 SwiftUI + WKWebView 客户端工程。

## 运行

需要 **Node.js 24.13+ 的 24.x**，无 npm 运行时依赖：

```bash
npm start
```

打开 <http://localhost:3000>，先注册/登录。默认监听 `0.0.0.0:3000`，同一局域网内的手机可访问 `http://电脑的局域网IP:3000`。外网域名、HTTPS、Mac launchd、备份和恢复见 [部署说明](DEPLOYMENT.md)。电脑需要保持开机和联网。

在 `.env` 配置 `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`、`MELIUS_MODEL`，格式见 `.env.example`；小课可用 `LESSON_MODEL` 与 `LESSON_TIMEOUT_MS` 单独配置。密钥只在服务端读取。AI 不可用时，手动记录和精选小课仍可使用。模型服务会接收用户主动发送的对话，以及用于个性化小课的相关减糖记录。

## 数据模型与兼容策略

- 正式数据库仍为 `data/quittr.sqlite`，账号和会话不变，不自动删除或重置已有数据。
- `user_state.data.sugar` 保存减糖饮食、渴望、回顾、目标和小课状态。
- 新日记在 `journal_entries` 中标记 `product: 'sugar'`；新聊天轮次在 `chat_turns` 使用 `sugar_` 命名空间。页面与 AI 只读取新产品对应的数据。
- `community_posts.product` 会自动补充：已有帖子标记为 `legacy`，新社区只展示 `sugar`。旧内容保留，但不能通过新社区入口查看或修改。
- `/api/account/export` 仍能导出所属账号的新旧完整数据。不要把导出的文件公开提交到 GitHub。
- 旧 `GET /api/quittr/*` 和部分兼容实现保留给历史数据与回归验证，当前界面不依赖这些指标；旧 blocker 和重置写入功能已经停用。
- 旧 `data/quittr-state.json` 仍不自动分配给任何人。它是本机兼容文件，不纳入版本控制；需要导入时见部署说明。
- 私人 API 均先鉴权，忽略客户端指定的其他用户归属。同一账号的异步写入按顺序处理；不同账号可并发。

主要业务接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/sugar/state?timeZone=Asia%2FShanghai` | 当前用户的减糖状态与按本地日期计算的统计 |
| POST | `/api/sugar/logs` | 保存饮食小记；`clientId` 防重复 |
| POST | `/api/sugar/cravings` | 保存当下渴望，不生成摄入记录 |
| POST | `/api/sugar/check-in` | 更新本地当天的温和回顾 |
| POST | `/api/sugar/preferences` | 保存小目标与可选个人参考值 |
| GET / POST | `/api/sugar/journal` | 获取 / 保存减糖心情日记 |
| POST | `/api/melius/chat` | 小轻流式对话，内部路径为兼容保留 |
| GET / POST | `/api/lessons/daily` | 精选 / AI 小课 |

## 营养信息与产品边界

本产品关注减少不必要的添加糖。**添加糖、游离糖、标签总糖不是同一个指标**；已知记录的添加糖之和不等于完整的每日摄入。不会根据照片、食物名字、奶茶甜度或杯型推算糖克数，也没有声称接入食品营养数据库。

小课中的一般信息参考 [WHO 糖摄入说明](https://www.who.int/news-room/detail/04-03-2015-who-calls-on-countries-to-reduce-sugars-intake-among-adults-and-children) 和 [NHS：Sugar, the facts](https://www.nhs.uk/live-well/eat-well/food-types/how-does-sugar-in-our-diet-affect-our-health/)。WHO 的游离糖定义包含蜂蜜、糖浆、果汁等中的糖；完整水果、蔬菜和天然乳糖不属于同一类。该说明不应被解释为必须戒除所有糖或碳水。

没有默认减重目标、身体评分、热量补偿或进食排名。涉及糖尿病、妊娠、进食障碍等个人医疗问题时，应与合适的专业人士讨论，不依赖本应用制定饮食处方。

尚未包含：自动食品识别、条码营养数据库、推送提醒、邮件验证/邮件找回密码、社区审核后台、自动异地备份、高可用集群。这些入口没有伪装成已实现的功能。忘记密码目前由管理员重置。

`ops/github-actions.yml` 是未启用的构建模板；当前 GitHub OAuth 凭据没有 `workflow` 权限，因此不会把模板直接上传为工作流。以上为本机实际构建结果，不代表 GitHub CI 已运行。

## 技术栈

原生 HTML/CSS/JS + 本地 React 18 UMD；Node.js HTTP；内置 SQLite；scrypt 密码哈希；HttpOnly 会话 Cookie；同源请求校验与限流；PWA 静态离线提示；SwiftUI + WKWebView。

数据库、备份、密钥、日志和真实用户记录不提交到 GitHub。字体来自 Google Fonts，不可达时使用系统字体。原型来源与技术命名的保留不代表与 QUITTR 官方存在关联。
